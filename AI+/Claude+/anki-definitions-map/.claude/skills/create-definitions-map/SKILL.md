# Anki definitions and their relationships

## Where the definitions are
- Read notes with the `anki-mcp` MCP server: `findNotes` to search, `notesInfo` to get the fields.
- Definitions are kept in the `Text` field of the `Programming-cloze` note type, as `{{c1::<dfn>Term</dfn>}} is {{c2::definition}}.`
- Terms are marked with `<dfn>` (or `<abbr>` / `<code>` for the defined term itself).
- Synonyms are notes tagged `synonym`; their cloze answers are the names (`{{c1::A}} is a synonym of {{c2::B}}`). The script attaches them to the defined terms as aliases, so they need nothing in relations.json.
- Abbreviations are `Programming` notes tagged `abbreviation` (`Question`: `Decipher <abbr>CA</abbr>`, `Answer`: `Certification Authority`, or a list of meanings). They aren't cloze notes, so they have a separate query. The script treats each as a synonym pair, so they also need nothing in relations.json.

## Workflow
Paths are relative to the project root. `scripts/build.py` does the parsing, link matching, sentence case and file generation; `scripts/map.html.tpl` is the finished HTML page. Change the template only when the user asks for a change to the page. Your part is the judgement in `out/<slug>/relations.json`. You don't need to read the script: its exit-2 output has the format and everything to fill in.
1. Run `python3 .claude/skills/create-definitions-map/scripts/build.py plan "<user query>"`. It prints the full query (`(<user query>) (tag:definition OR tag:synonym) note:*cloze*`), the abbreviation query (`(<user query>) tag:abbreviation`) and the slug.
2. Run `findNotes` with both queries. If the full query matches nothing, tell the user and stop.
3. Run `notesInfo` on the IDs from both queries, in batches of at most 100. Use the JSON file each result is saved to, or write the result to a file in the scratchpad if it comes back inline.
4. Run `python3 .claude/skills/create-definitions-map/scripts/build.py build "<user query>" <notes.json> [<notes.json> ...]` with the files from both queries.
5. If it exits with code 2, it prints what is missing from `out/<slug>/relations.json`: the title, links to classify (each with its source definition), terms to categorize, or stale relations to remove, plus a `format_example`. On the first run the script creates the slug folder with an empty starter file. Fill it in (keep earlier entries) following the rules below, and run step 4 again. Exit code 3 means no usable notes: report the skipped notes and stop.
6. Reply with the paths to the saved files (open `map.html` in a browser), the terms without a note, the synonyms and abbreviations without a definition, and any notes the script skipped.

## Rules for relations.json
- **Links:** a `<dfn>` inside a definition is a link. An `<abbr>` is a link only when it names a defined term or its initials (`JCA` → Java Cryptography Architecture).
- **Relationship:** pick it from the definition's wording: `inherit` for "is a kind of", `compose` for "is a part/field of", `aggregate` for "contains/stores", `depend` for "uses/manages/is generated by", and a labeled `assoc` otherwise.
- **Categories:** group the terms into at most 8 topics.
- **Proper names:** list product and standard names that keep their capitals (`Java Cryptography Architecture`). Everything else is shown in sentence case: `private key` → `Private key`, `Certification Authority` → `Certification authority`; acronyms and code names stay as they are (`IDL`, `X.509 certificate`, `keytool`).
- **Title:** a short name for the topic, such as "Cryptography definitions".

## Output
- `out/<slug>/definitions.md`: the two queries on the first lines, then the definitions with the cloze markers stripped, the term bold and in sentence case, its abbreviations and synonyms as "(stands for …; abbreviated …; also called …)", and the rest of the user's wording unchanged. Then the list of terms without a note, the synonyms whose names have no definition, and the abbreviations without a definition (`DN: Distinguished name`; several meanings are separated by `;`).
- `out/<slug>/diagram.mmd`: a Mermaid `classDiagram` in UML notation (`<|--`, `*--`, `o--`, `..>`, labeled `-->`). Synonyms are aliases, not nodes; two defined terms that are synonyms are joined by `--` labeled `synonym`. Terms without a note have the `<<missing>>` stereotype. The queries are `%%` comments after the `classDiagram` line, because the frontmatter must stay first. Don't add `style` lines: `classDiagram` fails to parse hyphenated CSS properties such as `stroke-dasharray`.
- `out/<slug>/map.html`, a standalone page (needs internet for d3 and fonts): an interactive force-directed map (d3) with drag, zoom and pan, topic colors and a legend, UML arrowheads, double lines between synonyms, dashed terms without a note, a "Find a term" search that also matches synonyms and abbreviations, a side panel with each term's definition, other names and links, the definitions list, and the Mermaid source in a collapsed section.
- `out/<slug>/relations.json`: the judgement above. The script never overwrites it; keep it between runs so only changed links need classifying.
- Slug (computed by the script): a single `tag:`/`deck:` query gives its name, otherwise the whole query; negation becomes `not-`, and everything except letters and digits becomes `-`. Examples: `tag:it::security::cryptography` → `it-security-cryptography`; `tag:it::network deck:Programming` → `tag-it-network-deck-programming`; `tag:a -tag:b` → `tag-a-not-tag-b`.
