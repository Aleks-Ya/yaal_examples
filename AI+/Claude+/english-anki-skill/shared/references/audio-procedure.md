# Audio procedure (shared)

The single home for how the four audio fields of an `En-word-or-sentence` note are filled:
`English-audio-generated`, `Definition-audio-generated`, `Synonym1-audio-generated`,
`Antonym1-audio-generated`. Both skills reach it through the backfill routine (step B3) and
`field-plan.md`'s audio rows. Each field's value, when filled, is `[sound:<filename>]`.

The helper scripts below are **run, never read** — their CLI contracts are documented here and in
`shared/references/field-plan.md`; don't open their source.

All four are generated by `shared/scripts/generate_tts.py` (Google Cloud TTS, voice
`en-US-Wavenet-B`, MALE, `en-US`, MP3, rate 1.0, pitch 0.0 — the HyperTTS preset).

## Which fields to generate

Each audio field pairs with a source text field (`English` → `English-audio-generated`, and likewise
for Definition / Synonym1 / Antonym1). Generate an audio field when its source text field is
**non-empty** and either:

- its own audio field is **empty**, or
- its source text was **just filled or changed this run** — then regenerate even if the audio field
  already holds a stale `[sound:…]`; the deterministic slug overwrites the old mp3 in place, so the
  field value itself is unchanged (see backfill-routine.md step B3).

`Synonym1-audio-generated` / `Antonym1-audio-generated` are skipped when Synonym1 / Antonym1 is
empty. `Synonyms-audio-generated` and `Antonyms-audio-generated` stay empty — they are not part of
this procedure.

## The text to synthesize

Take the source text **HTML-stripped**. `English` is used **verbatim** — keeping its `a`/`an`/`to`
prefix (see `shared/references/english-article-prefix.md`), which signals POS so heteronyms like
`a record` / `to record` are pronounced correctly.

## Synthesize, store, reference

1. **One call per note** — synthesize **all needed fields together**:
   `python3 "shared/scripts/generate_tts.py" --batch` with a JSON array of
   `{"text": ..., "path": "<temp.mp3>"}` on stdin. (Single-text form, if only one is needed:
   `generate_tts.py "<text>" <temp.mp3>`.)
2. **`storeMediaFile`** each result under its filename from the one
   `shared/scripts/slugify.py --all-media` call — see backfill-routine.md step B0 — e.g.
   `beggar-noun-english.mp3`: the Picture word+POS slug plus a field suffix, deterministic, so
   re-processing overwrites rather than accumulates.
3. **Delete the temp files** afterwards, and set each field to `[sound:<filename>]` in the note's
   single final write (backfill-routine.md steps B0/B3).

In dry-run mode skip the `storeMediaFile` and the write.
